# Учёба: трекер учебного времени

Минималистичный трекер для 2–3 друзей. Главный экран: таймер, цель недели и прогресс друзей. Страница «Репорты»: календарь и общий отчёт с выгрузкой в Markdown. В профиле: статистика, стрик, хитмап.

Стек: Next.js 16 (App Router) + TypeScript + Tailwind CSS 4, Supabase (Auth + Postgres с RLS), деплой на Vercel. Всё хранится в Supabase, локальных файлов нет.

## 1. Supabase

1. Создай проект на [supabase.com](https://supabase.com).
2. **SQL Editor → New query**: вставь содержимое [`supabase/schema.sql`](supabase/schema.sql) и нажми Run. Скрипт можно запускать повторно: после обновлений просто прогони его ещё раз.
3. **Authentication → Sign In / Providers → Email**: email-провайдер включён по умолчанию. Пароли не используются, вход только по magic link.
4. **Authentication → URL Configuration**:
   - **Site URL**: `https://<твой-домен>.vercel.app`
   - **Redirect URLs**: добавь `https://<твой-домен>.vercel.app/auth/confirm` и для локальной разработки `http://localhost:3000/auth/confirm`
5. **Authentication → Emails → Magic Link** (рекомендуется): замени ссылку в шаблоне на

   ```html
   <a href="{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email">Войти</a>
   ```

   Тогда ссылка работает, даже если письмо открыто на другом устройстве или в другом браузере. Со стандартным шаблоном тоже работает, но только в том же браузере, где запрашивали вход.
6. **Project Settings → API**: скопируй `Project URL` и `anon` / `publishable` key.

### Allowlist и закрытие регистрации

Приложение пускает только email из `ALLOWED_EMAILS`. Проверка стоит перед отправкой ссылки, после перехода по ней и на каждый запрос. Но anon key публичный, и через API Supabase в обход сайта зарегистрироваться технически можно. Поэтому **после того как все друзья вошли хотя бы раз**, выключи **Authentication → Sign In / Providers → Allow new users to sign up**. Существующие пользователи продолжат входить по ссылке.

Бесплатный SMTP Supabase отправляет всего несколько писем в час. Для 2–3 человек этого хватает, но если письма не приходят, подожди или подключи свой SMTP в **Authentication → Emails → SMTP Settings**.

## 2. Переменные окружения

| Переменная | Пример |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon / publishable key |
| `ALLOWED_EMAILS` | `me@gmail.com,friend@gmail.com` (через запятую, регистр не важен) |

Локально: `cp .env.example .env.local` и заполни.

## 3. Локальный запуск

```bash
npm install
npm run dev
```

Открой http://localhost:3000.

## 4. Деплой на Vercel

1. Запушь репозиторий на GitHub.
2. На [vercel.com](https://vercel.com): **Add New → Project** → выбери репозиторий. Фреймворк Next.js определится сам.
3. В **Environment Variables** добавь три переменные из таблицы выше.
4. **Deploy**.
5. Возьми домен проекта и пропиши его в Supabase (Site URL и Redirect URLs, шаг 1.4).
6. Если позже поменяешь `ALLOWED_EMAILS`, сделай Redeploy, чтобы переменная применилась.

## Как это устроено

- **Таймер** обновляется на экране мгновенно, а запросы в базу уходят в фоне по очереди. Сам таймер хранится в таблице `active_timers`, а не в браузере. Старт, пауза, продолжение, завершение и сброс выполняются Postgres-функциями (`start_timer`, `pause_timer`, …), которые берут время из часов базы (`now()`). Поэтому после обновления страницы или на другом устройстве таймер продолжается с того же места. Секунды на экране считает браузер.
- **Завершение** сначала ставит паузу, затем открывает форму отчёта с округлёнными минутами (их можно поправить, 1–960). `finish_session` в одной транзакции сохраняет сессию и удаляет активный таймер.
- **Дни** считаются по `Asia/Almaty`, время хранится в UTC. Сессия относится к дню, в который началась. Неделя начинается с понедельника.
- **Хитмап**: 5 уровней (0, до 30 мин, до 1 ч, до 2 ч, 2 ч и больше).
- **RLS**: читать могут все залогиненные, менять только свои строки.
- **Цель недели** хранится в `weekly_goals` (одна на человека на неделю, статус: в процессе / сделано / частично / не сделано). Цели друзей видны в их карточках.
- **Репорт** пишется в модалке после «Завершить»: одно поле, над ним вопросы-подсказки. Черновик сохраняется в `localStorage`, поэтому не теряется при обновлении страницы.
- **Инструкции «Как учиться»** лежат в [`content/instructions.md`](content/instructions.md). Текст можно править без изменения кода. Поддерживаются `#`, `##` и абзацы. Модалка открывается сама один раз, при первом входе (флаг `profiles.seen_instructions`).
- **Репорты** (`/reports`): фильтр по человеку, вкладки «Календарь» (месяц, часы и точки по людям, клик по дню показывает репорты) и «Общий отчёт» (неделя → день → человек, с целями недели). «Скачать .md» (`/api/export?range=7|14|30|all&u=<id>`) выгружает ровно то, что показано на экране.
- **Данные друзей** (часы, «сейчас учится», последний репорт) обновляются раз в минуту и при возврате на вкладку.

## Структура

```
supabase/schema.sql      таблицы, RLS, функции таймера, view user_totals
proxy.ts                 обновление сессии, allowlist, редиректы (бывший middleware)
app/login                вход по magic link
app/auth/confirm         подтверждение ссылки
app/onboarding           ввод имени при первом входе
app/page.tsx             главный экран: таймер + друзья
app/u/[id]               профиль: статистика, хитмап, имя, выход
app/reports              календарь и общий отчёт
content/instructions.md  текст «Как учиться»
app/api/export           выгрузка отчётов
components/              таймер и блоки дашборда
lib/                     Supabase-клиенты, даты, статистика, группировка репортов, markdown
```
